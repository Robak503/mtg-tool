# 1. TURN STRUCTURE OVERVIEW

## 1.1 The Five Phases

Every turn contains exactly five phases in this order, every turn, without exception:

| Phase | Steps | Priority given? |
|---|---|---|
| Beginning | Untap → Upkeep → Draw | Untap: No. Upkeep and Draw: Yes |
| Precombat Main | (no steps) | Yes |
| Combat | Beginning of Combat → Declare Attackers → Declare Blockers → Combat Damage → End of Combat | Yes in all steps except step skips |
| Postcombat Main | (no steps) | Yes |
| Ending | End → Cleanup | End: Yes. Cleanup: Normally no |

**Critical rule (500.1):** Every phase occurs every turn even if nothing happens during it. A player cannot "skip" to combat — each phase exists and must be traversed in order.

## 1.2 How Phases and Steps End (500.2 vs 500.3)

Two distinct ending rules apply:

**Phases/steps WITH priority (500.2):** End when the stack is empty AND all players pass in succession. The stack becoming empty alone is not enough — all players must pass after the stack is empty.

**Steps WITHOUT priority (500.3):** End when all specified turn-based actions for that step are complete. Only two steps use this rule: the untap step and certain cleanup steps.

## 1.3 Effect Durations at Step/Phase Boundaries (500.4–500.5)

- Effects lasting "until [step/phase] begins" expire as that step/phase begins (500.4)
- Effects lasting "until end of [step/phase]" expire as that step/phase ends (500.5)
- "Until end of combat" expires at end of the combat phase — not at the beginning of the end of combat step (500.5a)
- "Until end of turn" effects are handled specially in cleanup (500.5b → 514.2)
- Unspent mana empties at the end of every step and phase (500.5, 703.4q)

## 1.4 Beginning-of-Step/Phase Triggers (500.6)

When a phase or step begins, abilities that trigger "at the beginning of" that phase or step trigger immediately. They are put on the stack the next time a player would receive priority — via the standard 117.5 checkpoint process.

**This is the direct connection to Layer 4 (Trigger) and Layer 6 (Priority):** The beginning of each step/phase creates the event that beginning-of-step triggers detect. Those triggers then wait and are inserted before the active player gets priority at that step, per rule 117.3a.

# 2. EXTRA TURNS, PHASES, AND STEPS (500.7–500.12)

## 2.1 Extra Turns (500.7)

Extra turns are inserted directly after the current turn. If multiple extra turns are created, they are added one at a time — the most recently created turn is taken first (LIFO). If multiple players are given extra turns simultaneously, they are added in APNAP order, with the most recently added taken first.

## 2.2 Extra Phases (500.8)

Extra phases are inserted directly after the specified phase. Multiple extra phases created after the same phase also follow LIFO ordering.

## 2.3 Extra Steps (500.9)

Extra steps are inserted directly after (or before, if specified) a particular step. LIFO applies if multiple extra steps are created after the same step.

## 2.4 The "Step After a Phase" Rule (500.10)

If an effect adds a step after a particular phase (e.g., "additional upkeep steps after this phase"), the game creates a new instance of the phase that normally contains that step — but with all other steps skipped. Only the specified step occurs in that new phase.

## 2.5 Skipping (500.11)

To skip a step, phase, or turn is to proceed past it as though it does not exist. This is a replacement effect (rule 614.10). Effects that last "until" a skipped step never get to expire in that skipped step — they expire in the next step/phase of that type that actually occurs.

## 2.6 No Events Between Steps (500.12)

No game events occur between steps, phases, or turns. Actions happen within steps/phases, not in the transition between them.

# 3. BEGINNING PHASE (501–504)

## 3.1 Untap Step (502)

The untap step has three sequential turn-based actions, none of which use the stack:

**Action 1 — Phasing (502.1, 703.4a):** All phased-in permanents the active player controls that have phasing phase out; all phased-out permanents the active player controlled when they phased out phase in. Simultaneous.

**Action 2 — Day/Night check (502.2, 703.4b):** If the game has a day/night designation, it may change based on whether the previous active player cast spells.

**Action 3 — Untap (502.3, 703.4c):** The active player chooses which permanents they control untap, then untaps them all simultaneously. Normally all permanents untap.

**No priority (502.4):** No player receives priority during the untap step. No spells can be cast, no abilities activated, no abilities resolved. Any triggered ability that fires during the untap step waits in the waiting state until the first priority checkpoint — normally upkeep (503.1a).

**Untap step and the engine:** The 117.5 priority checkpoint does not run during the untap step. Triggers waiting from the untap step are placed on the stack along with upkeep triggers at the upkeep priority checkpoint.

## 3.2 Upkeep Step (503)

The upkeep step has no turn-based actions. The active player receives priority after the 117.5 checkpoint process runs, which places onto the stack:
- Any abilities that triggered during the untap step
- Any abilities that triggered "at the beginning of the upkeep"

These are all placed before the active player gets priority, in the standard two-part APNAP order (603.3b).

## 3.3 Draw Step (504)

Turn-based action: the active player draws a card (703.4d). This does not use the stack. Then the active player gets priority.

**Draw triggers:** Any ability that triggers when the active player draws (e.g., "whenever you draw a card") fires from the draw step's card draw and is placed on the stack before the active player gets priority.

**First turn exception (103.8a):** The player who goes first skips the draw step of their first turn in a two-player game.

# 4. MAIN PHASES (505)

## 4.1 Two Main Phases Per Turn

A standard turn has two main phases:
- **Precombat main phase:** Occurs before the combat phase
- **Postcombat main phase:** Occurs after the combat phase

Both are commonly called "the main phase." The precombat main phase is the *first* main phase. If the combat phase is skipped, the second main phase is still a postcombat main phase (505.1a).

## 4.2 Main Phase Has No Steps

A main phase ends when the stack is empty and all players pass in succession (500.2, 505.2). There are no steps to traverse.

## 4.3 Turn-Based Actions at Precombat Main Phase Start

Three turn-based actions occur at the start of the precombat main phase, in this order:
1. Scheme card set in motion (Archenemy only — 703.4e)
2. Lore counters placed on Sagas (703.4f)
3. Roll to visit Attractions (if any Attractions controlled — 703.4g)

All three happen before the active player gets priority.

## 4.4 What Can Be Cast in a Main Phase (505.6a)

The main phase is the only phase where a player can normally cast noninstant permanent spells and sorceries. Instants and abilities with instant speed can be cast or activated any time a player has priority.

## 4.5 Playing Lands (505.6b)

A land can be played during either main phase if:
- The stack is empty
- The active player has priority
- The player hasn't played a land this turn

Playing a land is a special action (rule 116). It doesn't use the stack, can't be countered, and players can't respond to it.

# 5. COMBAT PHASE (506–511)

## 5.1 Combat Phase Structure

```
Beginning of Combat
    ↓
Declare Attackers
    ↓  (skipped if no creatures declared or put onto battlefield attacking — rule 508.8)
Declare Blockers
    ↓  (skipped if no creatures declared or put onto battlefield attacking — rule 508.8)
Combat Damage (Step 1 — first strike/double strike only, if applicable)
    ↓  (second combat damage step only if first strike/double strike — rule 510.4)
Combat Damage (Step 2 — remaining creatures)
    ↓
End of Combat
```

## 5.2 Attacking and Blocking Objects

Only creatures can attack or block. Only players, planeswalkers, and battles can be attacked (506.3). A creature put onto the battlefield attacking or blocking never "attacked" or "blocked" for trigger purposes — it is attacking/blocking but did not attack/block as a declared action (508.4, 509.4).

## 5.3 Declare Attackers Step — The Declaration Sequence (508.1)

The declare attackers step proceeds through a locked sequence:

1. Choose which creatures attack and what they're attacking (508.1a–b)
2. Check restrictions — if any are violated, the declaration is illegal (508.1c)
3. Check requirements — maximize obeyed requirements without violating restrictions (508.1d)
4. Announce banding groupings if any (508.1e)
5. Tap chosen creatures — this is not a cost (508.1f)
6. Choose optional attack costs to pay (508.1g)
7. Determine total cost, lock it in (508.1h)
8. Activate mana abilities if needed (508.1i)
9. Pay all costs (508.1j)
10. Creatures become attacking creatures (508.1k)
11. Attack triggers fire (508.1m)

Then the active player gets priority (508.2). Triggers from the declaration process and from 508.1 go on the stack before priority is given (508.2b).

**Key precision — "attacks" vs "is put onto battlefield attacking" (508.3a):** A triggered ability reading "Whenever [creature] attacks" only fires if the creature was declared as an attacker. It does not fire if the creature is put onto the battlefield attacking. This is one of the most commonly adjudicated trigger distinctions in combat.

**Skip rule (508.8):** If no creatures are declared as attackers and no creatures are put onto the battlefield attacking, skip both the declare blockers step and the combat damage step entirely.

## 5.4 Declare Blockers Step — Key Trigger Distinctions (509.3)

| Trigger text | Fires when? |
|---|---|
| "Whenever [creature] blocks" | Declared as blocker or becomes blocker via effect — NOT if put onto battlefield blocking |
| "Whenever [creature] blocks a creature" | Once per attacking creature being blocked |
| "Whenever [creature] becomes blocked" | When it first becomes a blocked creature |
| "Whenever [creature] becomes blocked by a creature" | Once per blocking creature — ALSO fires if put onto battlefield blocking |
| "Whenever [creature] attacks and isn't blocked" | Fires in declare blockers step, not declare attackers step (509.3g) |

## 5.5 Combat Damage Assignment (510.1)

Combat damage is assigned in this order:
1. Active player announces how each attacking creature assigns its damage
2. Defending player announces how each blocking creature assigns its damage
3. Total assignment is checked for legality
4. If illegal, game returns to before assignment began (rule 732)
5. All assigned damage is dealt simultaneously (510.2) — no window between assignment and dealing

**Unblocked creatures assign to the attacked player/planeswalker/battle (510.1b).** If the creature isn't currently attacking anything (e.g., the planeswalker left), it assigns no damage.

**Blocked creatures:** Assign to blocking creatures. If all blockers left, no damage (510.1c).

## 5.6 First Strike / Double Strike (510.4)

If any attacker or blocker has first strike or double strike as the combat damage step begins:
- **Step 1:** Only first strikers and double strikers assign and deal damage
- **Step 2:** All remaining creatures (those with neither at the start of step 1) plus double strikers assign and deal damage

If no first strike/double strike creatures remain for step 2, step 2 is skipped.

## 5.7 End of Combat — Combat Removal (511.3)

As soon as the end of combat step ends, all creatures, planeswalkers, and battles are removed from combat. "Until end of combat" effects also expire at the end of the combat phase (511.2, 500.5a).

# 6. ENDING PHASE (512–514)

## 6.1 End Step (513)

The end step has no turn-based actions. The active player gets priority after 117.5 runs, which places beginning-of-end-step triggers on the stack.

**The non-backup rule (513.2):** If a permanent enters the battlefield during the end step with an ability that triggers "at the beginning of the end step," that ability does NOT trigger in the current end step. It waits for the next turn's end step. The step does not "back up." This also applies to delayed triggered abilities created during the end step that trigger "at the beginning of the next end step."

## 6.2 Cleanup Step (514)

The cleanup step has two sequential turn-based actions:

**Action 1 — Discard to hand size (514.1, 703.4n):** Active player discards to maximum hand size (normally 7). Does not use the stack.

**Action 2 — Damage removal and duration expiry (514.2, 703.4p):** Simultaneously — all damage removed from all permanents (including phased-out) AND all "until end of turn" and "this turn" effects end. Does not use the stack.

**Normally no priority (514.3):** After these actions, no player receives priority and the cleanup step ends.

**The cleanup exception (514.3a):** After the turn-based actions, the game checks for SBAs and waiting triggers. If either exists:
1. SBAs are performed
2. Waiting triggers go on the stack
3. Active player gets priority
4. Players may act
5. Once stack empties and all pass — another cleanup step begins
6. Repeat until a cleanup ends with no SBAs and no waiting triggers

**Why this matters:** Effects that create triggers in cleanup (e.g., "at the beginning of the next cleanup step"), or SBAs caused by damage removal (e.g., a creature that had damage preventing a lethal blow but the damage is now removed and it still has a -X/-X effect killing it), can cause cleanup to repeat. Each cleanup step is a fresh cleanup.

# 7. PRIORITY WINDOWS ACROSS THE TURN

| Step/Phase | Priority given? | Notes |
|---|---|---|
| Untap step | ❌ No | Triggers wait for upkeep |
| Upkeep step | ✅ Yes | Untap triggers + upkeep triggers placed first |
| Draw step | ✅ Yes | After draw turn-based action |
| Precombat main | ✅ Yes | After Saga/Attraction turn-based actions |
| Beginning of combat | ✅ Yes | After defending player chosen (multiplayer) |
| Declare attackers | ✅ Yes | After attack declaration and attack triggers |
| Declare blockers | ✅ Yes | After block declaration and block triggers |
| Combat damage | ✅ Yes | After damage dealt and damage triggers |
| End of combat | ✅ Yes | No turn-based actions |
| Postcombat main | ✅ Yes | No turn-based actions |
| End step | ✅ Yes | After end-step triggers |
| Cleanup step | ❌ Normally no | Exception: SBAs or triggers → priority opens |

# 8. CROSS-LAYER CONNECTIONS

## 8.1 → Layer 4 (Trigger)

Every beginning-of-step trigger in the game is generated by the rules in this layer. Rule 500.6 is the source rule for all "at the beginning of [step/phase]" triggers. Those triggers follow standard 603/117.5 insertion before priority is given at each step.

The untap step no-priority rule (502.4) is the basis for the L04_Trigger_engine.md §4.2 patch. The cleanup exception (514.3a) is the basis for §4.3.

## 8.2 → Layer 5 (State Enforcement)

The cleanup exception (514.3a) is where SBAs interact with the end of turn. Damage removal at cleanup (514.2) can change a permanent's state and trigger SBAs in the same cleanup step. Rule 703.3 establishes that turn-based actions happen before SBA checks — the sequence within a step is: TBAs → SBAs → triggers → priority.

## 8.3 → Layer 6 (Priority)

Rule 117.3a directly cites 703 (turn-based actions handled before priority) and 117.5 (SBA/trigger loop before priority). The priority window at each step is the result of this layer's rules feeding into Layer 6.

## 8.4 → Layer 3 (Event)

Combat damage dealing (510.2) is the event that damage-based replacement and prevention effects operate on. The L03 Event layer governs what happens to that damage event. The timing here — damage is dealt as a single simultaneous action with no window between assignment and dealing — is established by this layer.

# COMMANDER ADDENDUM — Turn Structure in 4-Player Free-for-All

Commander uses the standard turn structure (rules 500–514) without modification. The only differences are:

**Turn order:** Clockwise from the starting player. The active player takes their full turn, then the next player clockwise becomes active.

**Mana pools:** Each player's mana pool empties at the end of each step and phase (106.4), including between combat phases in a multi-combat turn. This is unchanged in Commander.

**"Beginning of [player's] upkeep" triggers:** In 4-player Commander, each player's upkeep triggers fire only during that player's upkeep step. If an effect says "at the beginning of each player's upkeep," it triggers once per player per full rotation of turns — four times total per round.

**Combat in Commander:** Under the Attack Multiple Players option (rule 802), a player attacks opponents individually — each creature attacks one opponent, and that opponent is the defending player for that creature. See `L10_Variant_800to811_t.md` (§3) for full treatment.
