# v0.21.0 Profiles — manual QA script (owner-run)

The multi-user profiles migration **mutates your real, irreplaceable data** the
first time you launch the upgraded `.exe`. It was verified in `npm run dev`
(which uses dev-tree paths), but **not** against real `%APPDATA%` inside the
packaged webview — which is exactly where the `.exe` runs. This script is the
~15-minute check that the upgrade is safe on real data.

Run **Part A** (upgrade over your existing data) first. Part B (fresh install)
is optional but proves the first-launch path. Every step has an explicit
**PASS** signal. If any check fails, stop and use **Rollback** at the bottom —
your data is recoverable from the backup the script makes.

> Paths below assume the installed app. Data lives at:
> `%APPDATA%\com.colton.mtg-tool\data\`
> (open it quickly with: `explorer "$env:APPDATA\com.colton.mtg-tool\data"`)

---

## Part A — Upgrade over existing data

### A0. Fully quit the app
Right-click the tray icon → **Quit** (the window's X only hides to tray; the
migration must not run while a second instance holds the data files).

```powershell
# Confirm nothing is still holding the data dir:
Get-Process mtg-tool, node -ErrorAction SilentlyContinue
```
**PASS:** no `mtg-tool` / bundled `node` processes listed.

### A1. Back up the real data dir (do NOT skip)
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"
$backup = "$env:APPDATA\com.colton.mtg-tool\data.pre-v0.21.0-backup"
Copy-Item $data $backup -Recurse -Force
"Backed up to $backup"
```
**PASS:** the backup folder exists and is non-empty.

### A2. Record the pre-migration state
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"
$decks = (Get-Content "$data\decks.local.json" -Raw | ConvertFrom-Json).decks
"Total decks: " + $decks.Count
$decks | Group-Object { $_.memory.owner } | Select-Object Name, Count
```
**Note the owners + counts** — e.g. `Colton 7`, `Joe 9`. The migration must
split decks into one profile per owner, with these exact counts.

### A3. (Optional) Seed a recovery file to exercise the sweep
The migration also sweeps pre-existing corruption-backup files into the primary
profile. To test that path, drop one in first:
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"
"{ broken json" | Set-Content "$data\decks.local.broken-20260101T000000.json"
```
(Recognized patterns: `decks.local.broken-*.json`, `collection.broken-*.json`,
`chats.local.json.corrupted`.)

### A4. Launch the upgraded app
Start MTG Tool normally and let it finish loading once.

### A5. Verify the on-disk migration
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"

# 1) Registry written, with one profile per owner you saw in A2:
$reg = Get-Content "$data\profiles.json" -Raw | ConvertFrom-Json
"Profiles: " + ($reg.profiles | ForEach-Object { $_.name }) -join ", "
"Active:   " + ($reg.profiles | Where-Object { $_.id -eq $reg.activeProfileId }).name

# 2) Decks split by owner into per-profile folders (counts should match A2):
foreach ($p in $reg.profiles) {
  $pd = (Get-Content "$data\profiles\$($p.id)\decks.local.json" -Raw | ConvertFrom-Json).decks
  "  $($p.name): $($pd.Count) decks"
}

# 3) Ownerless data moved into the PRIMARY (active) profile:
$primary = $reg.activeProfileId
"collection.json under primary: " + (Test-Path "$data\profiles\$primary\collection.json")

# 4) Recovery file (if seeded in A3) swept into the primary profile:
Get-ChildItem "$data\profiles\$primary" -Filter "*.broken-*" -ErrorAction SilentlyContinue |
  ForEach-Object { "swept: " + $_.Name }

# 5) Pre-migration backup written, and the legacy FLAT decks file removed:
"backup dir exists:     " + (Test-Path "$data\.pre-profiles-backup")
"legacy flat decks gone:" + (-not (Test-Path "$data\decks.local.json"))
```
**PASS, all of:**
- Active profile is **Colton** (it wins ties when present), and there's one
  profile per owner from A2.
- Per-profile deck counts **match A2 exactly** (Colton 7 → Colton profile has 7).
- `collection.json under primary` is **True**.
- The seeded recovery file (if any) shows as **swept**.
- `backup dir exists` is **True**.

> **`legacy flat decks gone` — `True` is expected, but `False` is NOT a
> failure.** The old combined `decks.local.json` is supposed to be deleted after
> the split, but on a real Windows install that delete can lose a race with a
> transient file lock and leave the original behind. It's **inert** — once the
> profile registry exists, the app only ever reads the per-profile copies and
> never this file — so your data is unaffected. The migration self-heals: it
> retries the delete on each later launch until it succeeds.

### A6. Verify in-app
- The **"Who's playing?"** gate appears. Pick the primary profile.
- Your decks and Vault collection are all there (nothing missing/duplicated).
- Switch to the other profile (header profile menu → switch). After the reload,
  you see **only that profile's** decks/Vault — no bleed from the first profile.

**PASS:** each profile shows only its own decks/Vault; nothing is lost.

### A7. Idempotency — second launch is a no-op
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"
$before = (Get-FileHash "$data\profiles.json").Hash
```
Quit (tray → Quit) and relaunch, then:
```powershell
$after = (Get-FileHash "$data\profiles.json").Hash
"registry unchanged on relaunch: " + ($before -eq $after)
```
**PASS:** `registry unchanged on relaunch: True` (migration ran exactly once).

## Part B — Fresh install (optional, ~5 min)

Proves the clean-machine first-launch path (no decks yet).

### B1. Set your real data aside
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"
# Quit the app first (tray -> Quit), then:
Rename-Item $data "data.realbackup"
```

### B2. Launch
Start the app. **PASS, all of:**
- Migration creates a single profile named **Player 1** (check
  `profiles.json` as in A5).
- The **"Who's playing?"** gate renders (not blank, not stuck).
- Picking it opens the app with an **empty** deck list / Vault (no crash, no
  phantom decks).
- Creating a second profile from the header works and starts empty.

### B3. Restore your real data
```powershell
$data = "$env:APPDATA\com.colton.mtg-tool\data"
# Quit the app, then:
Remove-Item $data -Recurse -Force
Rename-Item "$env:APPDATA\com.colton.mtg-tool\data.realbackup" "data"
```

## Rollback (if any PASS failed)

```powershell
$root = "$env:APPDATA\com.colton.mtg-tool"
# Quit the app first (tray -> Quit), then restore the A1 backup:
Remove-Item "$root\data" -Recurse -Force
Rename-Item "$root\data.pre-v0.21.0-backup" "data"
"Restored. Report which check failed so the migration can be fixed before re-trying."
```

The migration also writes its own advisory copy to
`data\.pre-profiles-backup\` before moving anything, so even without the A1
backup the originals are recoverable.

---

### Cleanup (after everything passes)
```powershell
# Optional: remove the A1 backup once you're confident.
Remove-Item "$env:APPDATA\com.colton.mtg-tool\data.pre-v0.21.0-backup" -Recurse -Force
```
